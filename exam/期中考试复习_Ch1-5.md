## Ch 1：互联网架构、Client/Server、HTTP

### 1.1 互联网与 C/S 模型
- **Internet**：网络的网络（network of networks），靠共同的**协议（protocols）**通信。
- **Client/Server 模型**：Client（浏览器/App）发请求；Server 存储并交付资源。餐厅类比：顾客=client，厨房=server，上菜=response。一台 server 可同时服务成千上万 client。
- **静态 vs 动态网页**：
  - **静态**：同一 URL 永远返回相同内容（服务器上的 HTML 文件），URL 一般无参数，纯信息性。
  - **动态**：内容根据用户操作/参数变化，既功能性又信息性。

### 1.2 DNS 与 IP
- **DNS**（Domain Name System）= 互联网的"电话簿"，把域名翻译成 IP 地址。
- **DNS 解析步骤**（顺序记牢，常考）：① 浏览器缓存 → ② 操作系统缓存 → ③ ISP 的 DNS 服务器 → ④ 根服务器 → ⑤ 域名的权威服务器。结果会被缓存以加速下次查询。
- **IPv4 vs IPv6**：

| | IPv4 | IPv6 |
|---|---|---|
| 位数 | 32 位 | 128 位 |
| 地址数 | ~43 亿 | ~340 undecillion（几乎无限）|
| 写法 | 四段十进制点分 `192.168.0.1` | 十六进制冒号分 `2001:0db8:...:7334` |

  - 双栈模式（**dual-stack**）= IPv4 与 IPv6 并存过渡。

### 1.3 协议分层 / TCP/IP（4 层，常考顺序）
1. **Link 链路层**：物理网络（Ethernet、Wi-Fi）
2. **Network 网络层**：IP——寻址
3. **Transport 传输层**：TCP / UDP——保证数据交付
4. **Application 应用层**：HTTP、DNS、邮件协议

- **TCP 三次握手**：SYN → SYN-ACK → ACK（建立连接后才传数据）。

### 1.4 HTTP——Web 的语言
- **HTTP = HyperText Transfer Protocol**，应用层协议，封装"提供网页"的过程。
- **无状态（stateless）**：服务器不保留过去请求的信息 → 所以才需要 Cookie/Session。⭐高频考点
- 几乎总跑在 **TCP** 上，**well-known 端口 80**（HTTPS 为 **443**）；一个连接可支持多次请求-响应。
- 其他应用层协议：FTP、SMTP、POP。

**HTTP 请求结构（Client → Server）**
- **Method**：`GET`（取数据）、`POST`（发数据/表单）、`PUT`（更新）、`DELETE`（删除）
- **Path**：请求的资源，如 `/products`
- **Headers**：`Host:`、`User-Agent:`、`Accept:` 等
- **Body**（可选）：登录凭据、表单、JSON

**HTTP 响应结构（Server → Client）**
- **Status line**：如 `HTTP/1.1 200 OK`
- **Headers**：`Content-Type`、`Content-Length`、`Set-Cookie` 等
- **Body**：HTML / JSON / 图片 / 视频

**报文格式**：起始行 + 0~N 个 header（`字段名: 值`，CRLF）+ 一个空行（标记 header 结束）+ 可选 body。Ver 1.1 中请求必须有 `Host:`。

### 1.5 HTTP 状态码（按类记，记住代表值）⭐

| 类 | 含义 | 常见码 |
|---|---|---|
| 1xx | Informational | 100 Continue、101 Switching Protocols |
| 2xx | Success | **200 OK** |
| 3xx | Redirection | **301 Moved Permanently**、307 Temporary Redirect |
| 4xx | Client Error | 400 Bad Request、401 Unauthorized、**403 Forbidden**、**404 Not Found**、408 Timeout |
| 5xx | Server Error | **500 Internal Server Error**、503 Service Unavailable、504 Gateway Timeout、505 HTTP Version Not Supported |

### 1.6 URL 格式 ⭐
```
<scheme>://<host>:<port>/<path>;<parameters>?<query>
```
- scheme=协议（http）；host=主机名/IP；port=端口（http 默认 80）；query=传参数。

### 1.7 Client → Server → Database 流程
浏览器 POST 用户名密码 → 服务器查数据库验证 → 返回结果 → 加载个性化页面。
完整流：**Client → Web Server → Application Logic → Database → 原路返回**。

### 1.8 其他概念
- **Cookies**：存在浏览器的小数据，每次请求都带上。
- **Sessions**：存在服务器，靠 session cookie 关联。
- **Caching**：缓存响应，减少访问服务器。
- **HTTPS**：用 TLS 加密的 HTTP，银行/密码/隐私必备。

## Ch 2：多层架构 + Django 入门（MVT）

### 2.1 为什么要分层 / 用框架（"单文件"的问题）⭐
单文件 all-in-one 应用的问题：
- **可扩展性差**：一个文件只能跑在一台机器，难以分摊负载。
- **可维护性差**：设计、逻辑、数据库调用混在一起，改动易牵连，新人难懂。
- **安全性差**：各部分无隔离墙，一个 bug 可能暴露数据。
- 100 万用户时**最先崩的是数据库**（连接耗尽/变慢），其次是 web server/应用代码。
- 简单缓解：加 **cache/CDN**、跑多份应用副本分摊负载、慢任务用**队列**。

### 2.2 架构演进
- **两层（Two-tier）**：富客户端直连数据库（MS Access、Oracle Forms/PowerBuilder、Java Swing/.NET WinForms 直连 SQL）。逻辑分散在客户端代码和数据库存储过程。
- **三层（Three-tier）**⭐：

| 层 | 职责 | Django 对应 |
|---|---|---|
| **Presentation 表示层** | 用户所见：HTML/CSS/JS、模板 | **Templates** |
| **Logic/Application 逻辑层** | 业务规则（如"用户名密码匹配则登录"）| **Views** |
| **Data 数据层** | 存储数据：SQLite/PostgreSQL/MySQL | **Models（通过 ORM）** |

- **N-tier / 微服务**：Clients → **API Gateway**（单一入口，做认证、负载均衡、限流、聚合响应）→ 各独立微服务（User Service、Payment Service…）→ Data Layer。
  - 优点：**Scalability**（各服务独立扩展）、**Flexibility**（独立开发部署）、**Resilience**（一个服务挂不一定拖垮全局）。

### 2.3 Web 框架与 Django
- **框架**：把"样板代码（boilerplate）"标准化，提供预制组件，强制良好实践，内置安全（登录/session）。缺点：限制编码范式、学习曲线陡。
- 其他框架：ASP.NET(C#)、Struts(J2EE)、Ruby on Rails、PHP/Perl 等。
- **Django**：高级 Python Web 框架，"为有截止日期的完美主义者准备"。
  - 核心理念：**DRY（Don't Repeat Yourself）**、快速开发、最佳实践、免费、强大。
  - 内置：认证、**Admin 后台**、**ORM**、模板、路由。
  - 用户：Instagram、Pinterest、Mozilla、NASA、Disqus、National Geographic、OpenStack。

### 2.4 MVC vs MVT ⭐⭐（必考映射）

| MVC | MVT（Django） | 职责 |
|---|---|---|
| Model | **Model** | 数据表示/访问；改 model 会改数据库 schema |
| View（显示）| **Template** | 描述数据如何呈现（渲染 HTML，可生成任意文本如 csv）|
| Controller（中介）| **View** | 描述呈现哪些数据；承载大部分逻辑，绑定 URL，返回 HttpResponse |

请求流：**Browser → URLconf → View → Model → Database → 原路返回 → Template → Response**。

### 2.5 项目搭建命令（务必背熟）⭐
```bash

建 app 后要把 app 名加入 `config/settings.py` 的 **`INSTALLED_APPS`**。

```

- 默认安装的 app：`admin`、`auth`、`contenttypes`、`sessions`、`messages`、`staticfiles`。

## Ch 3：Models / Views / Templates / ORM

### 3.1 Models（数据定义）
- Model = 继承 `models.Model` 的类：**类↔表，字段↔列，实例↔记录(行)**。⭐
- 定义在 app 的 `models.py`，开头 `from django.db import models`。

**字段类型**（常考）：
`CharField(max_length=…)`、`TextField`（无限长）、`IntegerField`、`DateField`、`DateTimeField`、`BooleanField`、`NullBooleanField`、`FileField`、`EmailField`/`URLField`/`IPAddressField`（底层像 CharField 但带校验）。

**字段选项**：
- `null=True`：数据库存 NULL（默认 False）。
- `blank=True`：表单允许留空（默认 False）。
- ⭐区别：`null` 是数据库层面，`blank` 是验证/表单层面。

**主键**：默认自动生成 `id = models.AutoField(primary_key=True)`（自增整数）。可自定义 `primary_key=True`（此时需自己保证唯一）。

**`__str__` 方法**：控制对象显示文本。

**Meta 内部类**：元数据，如 `ordering = ['name']`、`unique_together = ['name','age']`。

**模型继承**：可像普通 Python 类继承，避免重复字段（DRY）。继承隐含一个 one-to-one 关系。

### 3.2 关系（Relationships）⭐⭐

| 类型 | 字段 | 说明 |
|---|---|---|
| 多对一 | `ForeignKey(Class, on_delete=models.CASCADE)` | 只在"多"那端定义；反向可追溯 |
| 多对多 | `ManyToManyField(Class)` | 只在一端定义，默认对称 |
| 一对一 | `OneToOneField(Class)` | 一端定义；用于"扩展"另一对象 |

```python
class Company(models.Model):
    co_name = models.CharField(max_length=50)

class Car(models.Model):
    type = models.CharField(max_length=20)
    company = models.ForeignKey(Company, on_delete=models.CASCADE)
```
- 被引用的类必须**先定义**，或用字符串 `'Company'` / `'myApp.Company'`（跨文件）。
- 递归关系（自引用）：`models.ForeignKey('self')`。
- `limit_choices_to={'is_staff': True}`：限制可选值。

### 3.3 迁移（Migrations）⭐
```bash
python manage.py makemigrations   # 扫描 model 变更，生成迁移文件
python manage.py sqlmigrate app 0001  # 查看该迁移的 SQL
python manage.py migrate          # 把变更应用到数据库
```
- 生成 `db.sqlite3` 与 `0001_initial.py`。
- migrate 的前身是旧的 `syncdb`（1.7 前只能加表不能改/删）。

### 3.4 ORM 查询：Manager 与 QuerySet ⭐⭐⭐（重中之重）
- **为什么用 ORM**：可移植性（多数据库后端）、安全（防 SQL 注入）、表达力（高级查询语法）、封装（与 Python 集成、可加实例方法）。
- **Manager**：模型访问数据库的接口，每个 model 默认有名为 **`objects`** 的 Manager。
- **QuerySet**：可看作模型实例的列表，**惰性求值**，可迭代、索引、切片、链式组合。

**核心方法**：

| 方法 | 作用 | 返回 |
|---|---|---|
| `all()` | 取所有行 | QuerySet |
| `filter(**lookups)` | 符合条件的行 | QuerySet（可空可多）|
| `exclude(**lookups)` | filter 的反面 | QuerySet |
| `get(**lookups)` | 取**恰好一个** | 单个实例；无匹配→`DoesNotExist`，多匹配→`MultipleObjectsReturned` |
| `order_by(*fields)` | 排序，`-` 前缀降序 | QuerySet |
| `count()` / `exists()` | 计数 / 是否存在 | int / bool |
| `create(**kwargs)` | 创建并保存 | 实例 |

**字段查找（lookups）**：`name__contains`、`name__icontains`（忽略大小写）、`join_date__gte`、`length__lt` 等（双下划线）。

**切片** = SQL 的 LIMIT/OFFSET（不会先取全部）：`Student.objects.all()[:5]`、`[5:10]`。

**链式 / 组合**：
```python
Student.objects.filter(name="Alice").order_by("-join_date")[:3]   # Alice 中最新的 3 个
```

**CRUD 示例**（`python manage.py shell`）：
```python
Student.objects.create(name="Aisha", email="aisha@uwindsor.ca")  # Create
Student.objects.all()                       # Read
Student.objects.filter(name__icontains="a")
m = Student.objects.get(email="marco@uwindsor.ca")  # Update
m.name = "Marcus"; m.save()
m.delete()                                  # Delete
```

**反向关系**（FK 反查）：
```python
company = Company.objects.get(co_name='Ford')
cars = company.car_set.all()        # 默认 反向名 = 小写模型名_set
```

**M2M 查询练习**（Book/Author）：
```python
# Author.books = ManyToManyField(Book)
author = Author.objects.get(name='John Smith')
author.books.all()                  # John Smith 写的所有书
```

### 3.5 Views（视图）
- **View 函数**：接收 Web 请求 → 返回 Web 响应（HTML/重定向/404/XML/图片…），承载几乎所有逻辑（CRUD）。约定放在 `views.py`。
- Django 通过匹配请求 URL 选择 view（**只看域名后的部分**，不看 GET/POST 参数）。

**URLconf / `path()`** ⭐：
```python
path(route, view, kwargs=None, name=None)
```
- `route` 可含尖括号捕获：`<username>`、`<int:section>`、`<slug:title>`（slug=字母数字下划线连字符的短标签）。
- `name` 用于在别处反向引用 URL。
- **`include('app.urls')`**：把一组 URL 挂到某前缀下，Django 截掉已匹配部分，剩下交给被包含的 URLconf。除 `admin.site.urls` 外，包含其它 URL 都该用 include。
- `re_path()`：用正则，如 `re_path(r'^bio/(?P<username>\w+)/$', views.bio, name='bio')`。

**Web 应用完整流**：请求到 web server → 转给 Django → 建 request 对象 → 查 URLconf 找 view → 调用 view（传 request + 捕获的 URL 参数）→ view 返回 response → 回给 client。

**HttpRequest 属性**⭐：
- `GET` / `POST`：都是 **QueryDict**；GET 参数在 URL 查询串里，POST 在请求体里。
- `COOKIES`、`path`、`method`（'GET'/'POST'）、`FILES`、`user`、`session`。

**HttpResponse**：
- `status_code`、`content`；可 `HttpResponse("<html>…")` 或 `response.write(...)`；可像字典设 header：`response["Content-Type"]="text/csv"`。
- **子类**：`HttpResponseRedirect`、`HttpResponseForbidden`(403)、`HttpResponseNotFound`(404)、`HttpResponseBadRequest`(400)、`HttpResponseServerError`(500)。

## Ch 4：模板深入 + Forms + Sessions + Cookies

### 4.1 模板语言 ⭐
- **变量** `{{ variable }}`：求值后替换。变量名=字母数字下划线，不能以下划线开头，`.` 有特殊含义。
- **标签** `{% tag %} … {% endtag %}`：控制逻辑。
- **点查找（dot-lookup）顺序**⭐：① 字典查找 → ② 属性/方法查找 → ③ 数字索引查找；若结果可调用则无参调用它。

**过滤器（Filters）**：用管道 `|` 修改显示，可链式：
- `{{ name|lower }}`、`{{ text|escape|linebreaks }}`、`{{ story|truncatewords:50 }}`、`{{ list|join:", " }}`、`{{ join_date|date:"M d, Y" }}`、`{{ value|default:"(not set)" }}`、`{{ name|safe }}`（危险，见安全节）。

**常用标签**：
- `{% for x in list %} … {% empty %} … {% endfor %}`
- `{% if %}/{% elif %}/{% else %}/{% endif %}`
- `{% url 'name' arg %}`、`{% block %}`、`{% extends %}`、`{% include %}`、`{% load %}`、`{% static %}`、`{% csrf_token %}`

### 4.2 模板继承 ⭐⭐
- **base.html**（骨架）用 `{% block name %}{% endblock %}` 定义可覆盖区域。
- **子模板** 第一行 `{% extends "base.html" %}`，再覆盖对应 block。
```django
{% extends "classroom/base.html" %}
{% block content %} … {% endblock %}
```

### 4.3 去除硬编码 URL + 命名空间 ⭐
- 别写 `<a href="/myapp/{{ emp.id }}/">`，改用：`<a href="{% url 'myapp:detail' emp.id %}">`。
- **命名空间**：在 app 的 `urls.py` 加 `app_name = 'myapp'`，模板里用 `'myapp:detail'` 区分不同 app 中的同名 view。

### 4.4 静态文件
```django
{% load static %}
<link rel="stylesheet" href="{% static 'myapp/style.css' %}">
```
- 放在 `myapp/static/myapp/style.css`。

### 4.5 快捷函数 ⭐
- **`render(request, template_name, context=None, content_type='text/html', status=200)`**：模板 + context → HttpResponse。
- **`redirect(to)`**：返回 `HttpResponseRedirect`；参数可为 model（调 `get_absolute_url()`）、URL、view 名。
- **`get_object_or_404(Model, **kwargs)`**：调 `get()`，找不到抛 `Http404` 而非 `DoesNotExist`。

### 4.6 HTML 表单与 GET/POST ⭐
- `<form action="/url/" method="post">`：action=数据送往的 URL，method=HTTP 方法。
- **GET vs POST**（高频考点）：
  - GET：数据拼进 URL；只用于**不改变系统状态**的请求；可被书签/分享/重提交；不适合大量数据、二进制、密码（会出现在 URL）。适合搜索表单。
  - POST：数据在请求体；任何**会改变系统状态**的请求都该用 POST。

### 4.7 Django Form 类 ⭐⭐
```python
from django import forms
class NameForm(forms.Form):
    your_name = forms.CharField(max_length=100)
```
- Form 类描述表单结构；Form **Field** 映射到 HTML `<input>`，本身是类，负责校验。Field 在浏览器中表现为一个 **Widget**。
- 渲染时**不含** `<form>` 标签和提交按钮（需自己加）。

**Field 参数**：`required`（默认 True，空值抛 `ValidationError`）、`label`、`initial`、`widget`、`error_messages`（字典覆盖默认错误信息）。

**Widget**：字段对应的 HTML input 元素，负责渲染 HTML、从 GET/POST 提取数据。默认：CharField→TextInput、BooleanField→CheckboxInput、ChoiceField→Select、EmailField→EmailInput、MultipleChoiceField→SelectMultiple。可覆盖。

**Bound vs Unbound** ⭐：
- **Unbound（未绑定）**：无数据，`f = NameForm()`，渲染为空/默认值。`is_valid()` 永远 False。
- **Bound（已绑定）**：传入数据 `form = ContactForm(request.POST)` 或 `NameForm({'your_name':'Arunita'})`。
- `is_bound` 判断是否绑定数据。

**标准 view 处理模式**（必背）⭐：
```python
def contact(request):
    if request.method == 'POST':
        form = ContactForm(request.POST)     # 绑定提交的数据
        if form.is_valid():                  # 触发校验
            # 用 form.cleaned_data['subject'] ...
            return HttpResponseRedirect('/thanks/')  # PRG 模式
    else:
        form = ContactForm()                 # GET → 空表单
    return render(request, 'contact.html', {'myform': form})
```

**渲染选项**：`{{ form.as_p }}` / `{{ form.as_table }}` / `{{ form.as_ul }}` / `{{ form }}`。模板里：
```django
<form method="post">
  {% csrf_token %}
  {{ myform.as_p }}
  <input type="submit" value="Submit">
</form>
```
- label 由字段名生成（下划线→空格、首字母大写、默认加 `:`）；id 为 `id_<字段名>`。

**校验** ⭐：
- `is_valid()`：bound form 跑校验返回 bool，生成 `form.errors`。
- `form.cleaned_data`：校验后的数据字典，已转成 Python 类型（IntegerField→int 等）。
- `form.errors`、`form.non_field_errors()`、`form.<field>.errors`；渲染 bound form 会自动显示 `<ul class="errorlist">`。

### 4.8 ModelForm ⭐⭐
```python
from django.forms import ModelForm
class BookForm(ModelForm):
    class Meta:
        model = Book
        fields = ['title', 'pub_date', 'length']

form = BookForm()                       # 新增
form = BookForm(instance=book)          # 编辑已有
```
- 每个 model 字段自动对应一个 form 字段：`ForeignKey`→`ModelChoiceField`，`ManyToManyField`→`ModelMultipleChoiceField`；model 字段 `blank=True` → form `required=False`；有 `choices` → Select widget。
- **`save()`**：从绑定数据创建并保存数据库对象；`instance=` 则更新；`commit=False` 返回未保存的对象（需自己再 `.save()`）。
- 校验：调 `is_valid()` 或访问 `errors` 触发；`save()` 时若 `errors` 为真会抛 `ValueError`。

> 课堂例子（Week 4）：`StudentForm(forms.ModelForm)`，`Meta.model=Student, fields=["name","email"]`；view 里 `form.save()` 后 `redirect("student-list")`。

### 4.9 Sessions ⭐⭐
- **定义**：让 web 应用跨多次请求记住某用户信息（HTTP 本身无状态）。服务器存数据，浏览器只存一个 **sessionid** cookie。
- **工作流程**：首次请求 Django 建 session 并给 session ID → 浏览器把 ID 存 cookie（`sessionid`）→ 服务器存实际数据 → 之后每次请求自动带 sessionid → Django 据此查出 session 数据识别用户。
- **启用**：MIDDLEWARE 含 `SessionMiddleware`；INSTALLED_APPS 含 `django.contrib.sessions`（默认已配）。默认**数据库后端**存 session。
- **后端配置**（`SESSION_ENGINE`）：数据库 / 缓存（cache）/ 文件 / cookie-based（用加密签名 + SECRET_KEY）。

**`request.session` = 类字典对象**：
```python
request.session['fav_color'] = 'blue'    # 写（__setitem__）
fav = request.session['fav_color']       # 读（__getitem__）
fav = request.session.get('visits', 0)   # 安全读，带默认
del request.session['fav_color']         # 删
'fav_color' in request.session           # 判存在
# 还有 keys(), items(), setdefault(), clear()
```
- 默认**仅当 session 被修改时**才写回数据库。
- 课堂访问计数器：`visits = request.session.get("visits",0)+1; request.session["visits"]=visits`。

**重要方法**：
- `flush()`：删当前 session 数据并重新生成 key（确保旧数据不可再被访问，常用于登录/登出）。
- `set_expiry(value)`：int=多少秒后过期；datetime=指定时间；**0=浏览器关闭即过期**；None=用全局策略。
- `get_expiry_age()`、`clear_expired()`、`cycle_key()`（保留数据换新 key）。
- 测试 cookie：`set_test_cookie()`（一个 view 里设）→ `test_cookie_worked()`（**下一个**请求/view 里查，不能同一 view）→ `delete_test_cookie()` 清理。

**过期与清理**：
- `SESSION_EXPIRE_AT_BROWSER_CLOSE`：默认 **False**（cookie 存 `SESSION_COOKIE_AGE` 时长，不必每次重登）；True 则关浏览器即失效。
- Django **不自动清理**过期 session；需定期跑 `clearsessions`（建议设为每日 cron）。用户手动 logout 才删行，否则行一直留着。

### 4.10 Cookies ⭐
- **定义**：存在浏览器的小数据；含 name、value、可选设置（过期、domain、path、secure flag）。
- **工作流程**：服务器在响应里发 `Set-Cookie: sessionid=...; Path=/; HttpOnly` → 浏览器存 → 之后请求自动带 `Cookie: sessionid=...` → 服务器据此识别用户。
- **自定义 cookie**：
```python
def set_fav_color(request):
    resp = HttpResponse("Favorite color set!")
    resp.set_cookie("favorite_color", "blue", max_age=3600)  # 1 小时
    return resp
```
- DevTools 查看：Application → Storage → Cookies；可见 Name/Value/Domain/Path/Expires/**HttpOnly/Secure/SameSite**。

### 4.11 Post/Redirect/Get（PRG）
- view 处理完 POST 后通常 **redirect** 到另一页，防止刷新导致重复提交。

## Ch 5：认证、授权、安全

### 5.1 Django 认证系统组成
User 对象 + 可配置的密码哈希系统 + 登录/限制内容的表单和工具 + **Permissions**（二元 yes/no 标志）+ **Groups**（给多用户批量贴标签/权限）。

**安装**：INSTALLED_APPS 含 `django.contrib.auth` + `django.contrib.contenttypes`；MIDDLEWARE 含 `SessionMiddleware` + `AuthenticationMiddleware`（默认已配）。

### 5.2 User 模型 ⭐
- 来自 `django.contrib.auth`，迁移后自动建表 **`auth_user`**。
- Django 只有**一个 User 类**——superuser/staff 只是设了特殊属性的 User，不是不同的类。
- 字段：`username`（必填、唯一、≤30 字符）、`password`（必填，存**哈希**不存明文）、`email`（可选）、`first_name`/`last_name`（可选）、`is_staff`（能登 admin）、`is_superuser`（绕过所有权限检查）、`is_active`（账号是否启用）。

**创建/改密**（必背）⭐：
```python
from django.contrib.auth.models import User
user = User.objects.create_user('john', 'lennon@x.com', 'johnpassword')  # 已存库
u.set_password('new password'); u.save()    # 改密码，绝不能 u.password = '...'
python manage.py createsuperuser              # 命令行建超级用户
```

### 5.3 认证 / 登录 / 登出 ⭐⭐
```python
from django.contrib.auth import authenticate, login, logout
user = authenticate(username='john', password='secret')  # 对→User，错→None
if user is not None:
    if user.is_active:
        login(request, user)     # 把已认证用户绑定到当前 session
# 登出
logout(request)                  # 清当前请求的 session 数据，无返回值
```
- `authenticate()` 验证凭据；`login()` 把用户 ID 存进 session。手动登录需**先 authenticate 再 login**。
- **`request.user`**：当前用户；未登录是 `AnonymousUser`，登录后是 `User`。用 **`is_authenticated`** 区分。

**URL 与模板（课堂做法）**：
```python
path("accounts/", include("django.contrib.auth.urls"))
# 免费获得 /accounts/login/、/accounts/logout/、/accounts/password_change/ 等
```
- 登录模板放 `templates/registration/login.html`；登出页 `registration/logged_out.html`；改密 `registration/password_change_form.html` / `password_change_done.html`（不建也有默认）。

### 5.4 限制访问：login_required ⭐
```python
from django.contrib.auth.decorators import login_required
@login_required
def profile(request):
    return render(request, "classroom/profile.html", {"user": request.user})
```
- 未登录 → 重定向到 `settings.LOGIN_URL`（默认 `/accounts/login/`），并在查询串附带 **`?next=`** 原路径，登录后跳回。

### 5.5 授权 vs 认证 ⭐

| 概念 | 含义 | 类比 |
|---|---|---|
| **Authentication 认证** | 确认"你是谁" | 出示学生证进楼 |
| **Authorization 授权** | 确认"你能做什么" | 进楼后能否进特定实验室 |

### 5.6 权限（Permissions）⭐⭐
- 每个 model 自动建 **4 个默认权限**：**add / change / delete / view**。
  - 检查：`user.has_perm('myapp.add_book')`（形式：`"<app label>.<codename>"`，codename 如 `add_<model>`）。
- view 中检查：
```python
from django.contrib.auth.decorators import permission_required
@login_required
@permission_required('classroom.add_student', raise_exception=True)
def add_student(request): ...
# 无权限 → 403 Forbidden
```
- 手动检查：`if request.user.has_perm('libapp.can_search'): ...`
- 模板中：`{% if perms.classroom.add_student %} … {% endif %}`
- 用户权限（M2M `user_permissions`）：`.set([..])` / `.add()` / `.remove()` / `.clear()`。
- **自定义权限**：用 `Permission.objects.create(codename=, name=, content_type=)`。

### 5.7 Groups（组）
- 给一组用户批量赋权；组内用户自动获得组权限。
- 用户 M2M `groups`：`.add()` / `.remove()` / `.set()` / `.clear()`；`group.permissions.add(permission)`。
- 课堂例子：Admin 建 `Teachers` 组（勾 view/add/change/delete student）、`Viewers` 组（仅 view），再把用户分到组。

### 5.8 安全最佳实践 ⭐⭐⭐（必考）

| 威胁 | 含义 | Django 防护 |
|---|---|---|
| **CSRF** 跨站请求伪造 | 诱使已登录用户执行非本意操作（恶意站点向你的 `/students/add/` 发 POST）| **CSRF 中间件** + 每个 POST 表单加 **`{% csrf_token %}`**（token 由 Django 生成、存 session、随表单提交；不匹配→**403 Forbidden, CSRF verification failed**）|
| **XSS** 跨站脚本 | 注入 JS（如评论框输入 `<script>`）| Django **默认转义** `<`、`>`、`"` 等危险字符。**`{{ x|safe }}` 会关闭转义——除非完全信任数据否则绝不用** |
| **密码盗窃** | 明文密码泄露 | **密码哈希**：单向变换，默认 **PBKDF2**（加唯一 **salt** + 数千轮哈希）。绝不存明文，泄库也无法还原 |
| **HTTP 明文** | 同 Wi-Fi 可读/改流量、窃取 session cookie | **HTTPS = SSL/TLS 加密**；部署时（Heroku/Azure）配置 |

- CSRF token 示例：`<form method="post"> {% csrf_token %} … </form>`。漏写则 403。
- 密码哈希存储样例：`pbkdf2_sha256$600000$FX8fM4PrA9xM$8QH...`（算法$轮数$salt$hash）。

## 高频考点速记（Cheat Sheet）

- **HTTP 是 stateless**；Cookie 存浏览器、Session 存服务器靠 `sessionid` 关联。
- **状态码**：200/301/400/401/403/404/500——会写含义。
- **DNS 解析 5 步**：浏览器缓存→OS 缓存→ISP→根→权威。
- **三层架构 ↔ Django**：Presentation=Template，Logic=View，Data=Model(ORM)。
- **MVC→MVT**：Controller=View，View=Template。
- **命令**：`startproject` / `startapp` / `makemigrations` / `migrate` / `runserver` / `createsuperuser` / `shell`。
- **类↔表，字段↔列，实例↔行**；默认主键 `id` AutoField。
- **`null`（数据库）vs `blank`（表单）**。
- **关系**：FK=多对一（`on_delete=CASCADE`），M2M，O2O；反查 `xxx_set.all()`。
- **QuerySet**：惰性、可链式、可切片(=LIMIT/OFFSET)；`get()` 唯一否则抛异常；lookups 用 `__`。
- **`objects`** 是默认 Manager。
- **GET vs POST**：GET 不改状态、进 URL；POST 改状态、进 body、表单/密码用 POST。
- **Form vs ModelForm**；`is_valid()`→`cleaned_data`；`{% csrf_token %}` 必加。
- **render / redirect / get_object_or_404**。
- **认证三函数**：`authenticate()` → `login()` / `logout()`；`request.user.is_authenticated`。
- **`@login_required`**（→LOGIN_URL，带 `?next=`）、**`@permission_required`**（→403）。
- **默认权限 4 个**：add/change/delete/view；`has_perm('app.codename')`。
- **安全四件套**：CSRF（csrf_token）、XSS（自动转义、慎用 `|safe`）、密码哈希（PBKDF2+salt）、HTTPS（TLS）。
