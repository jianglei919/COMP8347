You will have 10 MCQ questions of Level II.

These questions are code-based MCQ questions.

     

Example:

Consider the following Django REST Framework view: 

# views.py
from rest_framework.decorators import api_view
from rest_framework.response import Response
from .models import Student
from .serializers import StudentSerializer

@api_view(['GET'])
def student_list(request):
    students = Student.objects.all()
    serializer = StudentSerializer(students)
    return Response(serializer.data)

What is the main problem with this code?

A) The view is missing @permission_classes([AllowAny]), so it will always fail.
B) StudentSerializer should be initialized with many=True when serializing a queryset.
C) The function must be named get_students for DRF to recognize it.
D) Response(serializer.data) must be replaced with JsonResponse(serializer.data, safe=False).

     

Explanation:

B) StudentSerializer should be initialized with many=True when serializing a queryset.

Student.objects.all() returns a queryset (a list-like collection of Student objects). In Django REST Framework, when you pass a queryset to a ModelSerializer, you must specify many=True, otherwise DRF expects a single object and raises an error.

    

The corrected code should be:

      

@api_view(['GET'])
def student_list(request):
    students = Student.objects.all()
    serializer = StudentSerializer(students, many=True)
    return Response(serializer.data)

   

You will have 10 short-answer questions of Level I.

These questions are simple short-answer questions (no explanation required).

       

Example: 

In GraphQL, what keyword is used to define a data-modifying operation (e.g., create, update, delete)?  __________________________

    

Answer:

Mutation

     

Explanation:

In GraphQL, a mutation is used to change data (create, update, delete). When you modify the database, the operation must be wrapped inside a mutation block. This tells the GraphQL server that you are requesting a change, not just reading data.

       

You will have 5 short-answer questions of Level II.

    

Example:

Write a safe Django ORM equivalent for this vulnerable query:

      

SELECT * FROM users WHERE id = user_input;

(You only need one line of Python code.) 

  

Answer:

User.objects.get(pk=user_input)

      

       

Explanation:

This prevents SQL injection by parameterizing the query through the ORM, instead of concatenating raw SQL.
